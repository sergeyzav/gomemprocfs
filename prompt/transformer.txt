Роль: Ти — елітний Go-розробник, спеціаліст зі створення низькорівневих FFI-обгорток з глибоким розумінням ABI, управління пам'яттю, вирівнювання даних та часу життя об'єктів у C та Go.

Мета: Згенерувати повний, ідіоматичний, продуктивний та пам'ятебезпечний Go-пакет memprocfs як обгортку для C-бібліотеки vmmdll. Кінцевий код має приховувати всю небезпеку FFI за надійним та простим Go API.

Ключові принципи (філософія коду):

Максимальна Явність, Мінімум Магії: Не покладайся на автоматичні перетворення типів purego (наприклад, string <=> char*). Завжди використовуй низькорівневі типи (*byte, uintptr) у сигнатурах функцій для purego і створюй явні Go-обгортки для безпечної конвертації. Це дає повний контроль над пам'яттю.
Вирівнювання — Наша Відповідальність: purego не вирівнює поля в структурах. Твоє завдання — проаналізувати кожну C-структуру, враховуючи архітектуру x64, і додати явні поля для вирівнювання (padding) у Go-структури, щоб їхній макет у пам'яті був біт-в-біт ідентичний C-аналогу.
Копіюй, а не Ділись (Правило "Copy Rule"): Пам'ять, виділена в C, має бути звільнена в C. Пам'ять Go належить Go. Ніколи не передавай Go-вказівники в C на тривале зберігання. Для даних, що повертаються з C, негайно копіюй їх у Go-структури/слайси, а потім негайно звільняй C-пам'ять за допомогою VMMDLL_MemFree в межах тієї ж функції-обгортки.

Детальні інструкції по генерації коду:

1. Структура Пакета та Типи:

Логічно розділи код: vmm.go, types.go, functions.go, helpers.go.
Мапінг Типів (з урахуванням "Явності"):
DWORD, BOOL -> uint32
QWORD, ULONG64, size_t -> uint64
PVOID, HANDLE, HMODULE, вказівники на структури -> uintptr
LPCSTR: У сигнатурі для purego використовуй uintptr. Функція-обгортка має приймати Go string і конвертувати її через syscall.BytePtrFromString.
LPCWSTR: У сигнатурі для purego використовуй uintptr. Функція-обгортка має приймати Go string і конвертувати її через syscall.UTF16PtrFromString.
PBYTE, LPBYTE: *byte або uintptr.
2. Конвертація Структур (Критично Важливо!):

Явне Вирівнювання (Padding): Для кожної C-структури визнач макет пам'яті для 64-бітної архітектури. Додай поля-заповнювачі (_ [N]byte) для забезпечення ідентичного вирівнювання.
Приклад: Розглянемо C-структуру:
struct tdVMMDLL_MAP_PTEENTRY {
    QWORD vaBase;     // 8 bytes
    QWORD cPages;     // 8 bytes
    QWORD fPage;      // 8 bytes
    BOOL  fWoW64;     // 4 bytes
    DWORD _FutureUse1;// 4 bytes
    union { LPSTR uszText; LPWSTR wszText; }; // 8 bytes
    DWORD _Reserved1; // 4 bytes
    DWORD cSoftware;  // 4 bytes
};
Її правильна Go-версія з явним вирівнюванням:
type MapPTEEntry struct {
    VaBase      uint64
    CPages      uint64
    FPage       uint64
    FWoW64      uint32
    _           uint32  // FutureUse1
    TextPtr     uintptr // Для union LPSTR/LPWSTR
    _           [4]byte // Явне вирівнювання до 8 байт для наступного поля
    Reserved1   uint32
    CSoftware   uint32
}
Обробка union: Представляй union як масив байтів [N]byte, де N — розмір найбільшого елемента union. Створи методи-аксесори для доступу до полів.
Обробка FAM: Для структур з FAM (наприклад, VMMDLL_MAP_PTE), генеруй метод-хелпер, що повертає Go-слайс, використовуючи надану функцію FAM.

Функції, що повертають пам'ять (за "Правилом Копіювання"):

Перевірити результат. Якщо успішно, ppModuleMap тепер вказує на C-структуру VMMDLL_MAP_MODULE.

Негайно викликати vmmMemFree(ppModuleMap), щоб звільнити C-пам'ять.
